# Critical Session History

This is not a full transcript. It preserves decisions and feedback that materially change future work.

## Phase 1 — Hold'em structure replaces traditional mahjong focus

- Goal became “Mahjong Texas Hold'em.”
- Discard/call/river/furiten complexity was deliberately demoted.
- Main loop became board → private information → range/equity → bet → reveal → bet.
- 116-tile and 13+4+3/1/1 hypotheses were created to mimic Hold'em probability bands.

## Phase 2 — tenpai must be emotionally obvious

- Fatal issue: the player could not understand the state instantly.
- Desired emotion: casino/pachinko reach, visibly one tile away.
- Wait candidates should be clear supporting information.
- If a winning tile is held, it should light.
- Replaceable/usable tiles should be framed.
- Ordinary narrow mahjong tiles temporarily replaced spherical/novel forms to improve comprehension.

## Phase 3 — communal field and final hand

- Communal reveals became the main central mechanism.
- Initial 15 arranged 5 × 3 became the promising playable baseline.
- Later +4 groups remained visually separate.
- Private eight tiles sit closer to the player.
- Final 14 tiles span the bottom edge in one row and act as a second protagonist.
- Source tiles dim when selected.
- No automatic tile replacement at 14.
- Selection persists across reveals.

## Phase 4 — first genuine gameplay promise

- User found seven pairs manually.
- Narrowly completing or failing to complete felt fun.
- High-scoring routes appeared.
- The imperfect recommendation system sometimes failed to find strong hands such as four concealed triplets; this unexpectedly preserved player discovery.
- Riichi/tsumo direction was discussed, with no ippatsu.

## Phase 5 — visual mock breakthrough but implementation mismatch

- A generated premium casino/arena mock approached the desired product feeling.
- Full-screen use as a base64/static image reproduced appearance but was not interactive.
- Attempts to add dragging/free movement misunderstood the simple tap-to-final-hand requirement.
- User concluded that individual assets plus a coding agent would be faster than fake interaction.
- Claude then improved asset decomposition, scoring, flow, and acceptance tests in GitHub.

## Phase 6 — asset-light construction remains cheap

- User objected to building everything as SVG/CSS without real game assets.
- Current background helped, but temporary UI details still looked improvised.
- User asked for modern game-development practice: use existing free/paid assets where useful, choose final platform from the target, and avoid work that must later be rebuilt.
- Strong directive: imagine the perfect final target first and work backward.

## Phase 7 — selection and concentration

- User clarified that “worldbuilding” does not mean an explorable world.
- The advantage of strong individual-developed games is that visible seams are minimized.
- Concentrate on a tiny number of beautiful objects and moments.
- Balatro’s tactile card selection was cited as the kind of small interaction that can carry quality.

## Phase 8 — broad product exploration

- User requested 15–20 image mocks in smartphone HTML.
- Asked to expand beyond tiny changes into buttons, characters, lobby, gacha, and the full Poker Chase product envelope.
- V2 produced 18 screens.
- Selection recorded as KEEP 1,5,7,8,10,11,13,14,15,16,17,18; DROP 2,3,4,6,9,12.

## Phase 9 — remove AI over-rendering

- User praised the breadth but criticized obvious ChatGPT-style “gabigabi.”
- Suspected causes: hidden wave-like pattern language and excessive rendering/detail.
- Requested lighter backgrounds and a clean, refined screen.
- Clean Visual Standard was established.
- Three Clean Masters were generated: lobby, gacha, match.

## Phase 10 — strongest positive verdict and next request

- User: “震えるほど一気にこれまでの5千倍前進.”
- Still wants detailed correction and more directions.
- Wants to resolve expensive large decisions before implementation.
- Suggests a Future-Mahjong-style HTML gallery with 50 directions.
- Suggests defining five higher-level macro directions before detailed breakdown.

This is the current frontier.
