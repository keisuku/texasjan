# texasjan 再始動 — 一局の勝負を磨く

2026-09-07 / 実装ブランチ `build/holdem-restart-20260907`

## 判断

目指す体験は **「4枚めくるたびに勝負が変わる。牌を読み、相手を読み、張るか降りるかを決める」**。

世界での成功に近づくには、最初の一局で理解でき、何度遊んでも判断が変わり、勝敗に納得できることが必要だと考える。画面数やガチャ商品数は、その後の課題。今回の実装はこの仮説を遊べる形にする第一段階であり、市場での成功や最終画風の承認を意味しない。

## 今回実装したこと

1. **賭けと取り分の整合。** ストリートをまたぐ支払台帳、サイドPOT、勝てる上限、未コール分の返却、同点時の分配を純粋なモジュールへ分離した。小額オールインがレイズ権を不適切に再開する問題も修正。
2. **CPUも固定牌を守る。** 完成形が見つからない場合も固定牌を保持。追加固定で推薦手の同種牌数を超える問題を修正。七対子の全候補と国士無双を探索対象へ追加。
3. **推薦を軽く、説明を正確に。** 選択肢の重複を抑えて探索し、4枚・6枚の推薦も一貫した完成候補から選ぶ。探索上限に到達した場合は「完成形がない」と断定しない。
4. **初回ガイドと判断表示。** 現在の段階、選ぶ枚数、追加支払額、支払済み額、残る公開枚数を説明。CPUの思考時間を1×/2×に変更できる。
5. **収支と振り返り。** 勝利の表示と点数の増減を分け、各判断時のPOT、支払い、実際の取り分を表示。直近40件を端末へ保存。保存が使えなくてもゲームは続けられる。
6. **同じ配牌で練習。** 牌山・CPU判断用の乱数を分離して再現可能にした。開始時の点数・席順へ戻って別の選択を試せる。練習はランク・通常の集計へ混ぜず、次の通常局では元の点数に戻す。
7. **途切れない進行。** フォールド後は残りの展開を一操作で進める。未決着のまま再開した際にPOTが消える問題、公開やベットの途中で決着できる問題、決着済みの牌を書き換えられる問題を修正。
8. **操作の補助。** 牌のキーボード選択、選択・固定状態の読み上げ、主要な結果・金額調整操作の44px以上のサイズ指定を追加。画面構図やキャラクター画風は新規確定していない。

## ルールの線引き

- 136牌、6席、私牌8、共通15→19→23→27、固定4→追加2、最終14という承認済み進行は継続。
- 既存の持ち点比例の参加料は、全参加者に権利がある**共通の参加料POT**として維持。追加ベットだけをサイドPOTの上限計算へ使う。これは標準ポーカーの少額アンティ規則と同一であるとは主張しない。
- 純粋な役判定 `mahjong-score.js` は変更しない。おすすめは指定した組み方の候補であり、最大得点・最適戦略・勝率の保証ではない。
- PR #43の29画像、#44、#45は引き続き不採用。PR #47の部品実験は別のdraftのまま。今回の実装で承認済み画風に昇格させていない。
- 端末内のCPU検証版。ネットワーク対戦、公的ランキング、決済には接続しない。

## 次の制作順

| 順序 | やること | 進める判断基準 |
|---|---|---|
| 1 | 実機で一局を遊び、選択と公開とベットの迷いを確認 | 操作説明なしで次の行動が分かる。画面外・重なり・押し間違いがない |
| 2 | 固定4→2と可変固定・固定なしを同じ配牌で比較 | 完成率だけでなく、固定後悔、勝者交代、分配率、ベット頻度を測る。新ルールは別実験として判断 |
| 3 | 対局画面一枚の完成見本を確定し、専用素材へ分解 | 通常・4枚公開・オールイン・勝利を同じ画面で比較。縮小して牌・POT・手番が読める |
| 4 | 固定牌を考慮するCPU方針を比較 | ランダムCPUより強いだけでなく、人間が読み合える。隠れた牌を参照しない |
| 5 | サーバーを正本とする対人戦と切断復帰 | 山・私牌・支払・勝敗をクライアントの申告に任せない |

Unity/Nakamaなど以前の案は比較候補。対局の価値と完成見本が定まる前に基盤移行を始めない。

## 残っている重要課題

- 通常CPUの自信評価は固定牌制約を直接計算しておらず、勝率推定ではない。
- CPUは和了牌を最適化して採点し、プレイヤーは最後に選んだ牌で採点する。ツモ枠のルールとして維持するか、双方へ自動最適化を入れるかを次に比較する。
- 固定後悔率・分配率の過去の500局値は旧推薦方針の結果。今回の方針変更後のバランス値として再使用しない。
- ブラウザのURL制約でこの環境の実画面テストを完遂できなかった。Nodeでの状態遷移・イベント検証と実ブラウザでのレイアウト・アニメーション検証は別。後者は未確認として残す。
